## 🌌 معرفی پروژه

**Neo-AI-Bot** یک ربات تلگرام مبتنی بر پایتون است که چند حالت مستقل برای گفتگو، برنامه‌نویسی، تولید تصویر و تولید ویدیو دارد. تنظیمات مدل‌ها، کاربران، تاریخچه و کانال‌های اسپانسر با استفاده از **Upstash Redis REST** نگهداری می‌شوند.

### نکات مهم دربارهٔ قابلیت‌های هوش مصنوعی

- **ساخت تصویر و ویدیو:** کارکرد مستقیم در تلگرام به API واقعی و قالب درخواست/پاسخ همان سرویس بستگی دارد. آدرس صفحهٔ معمولی سایت به‌تنهایی API نیست؛ در حالت سایت‌محور، ربات لینک سایت را باز می‌کند و تولید داخل تلگرام انجام نمی‌شود.
- **جست‌وجوی وب:** موتور جست‌وجوی مستقل Google/Bing/Brave/SearXNG در نسخهٔ فعلی وجود ندارد. وب‌گردی فقط وقتی انجام می‌شود که API مدل انتخاب‌شده ابزار جست‌وجوی بومی سازگار داشته باشد.
- **مدل‌ها:** نام مدل، endpoint و شیوهٔ احراز هویت را عین مستندات ارائه‌دهنده وارد کنید. سازگاری با API اوپن‌ای‌آی به معنی سازگاری خودکار با همهٔ APIهای تصویر و ویدیو نیست.
- **کاربران غیرقابل‌دسترسی:** خطای ارسال پیام لزوماً ثابت نمی‌کند کاربر ربات را بلاک کرده است؛ تلگرام فهرست قطعیِ «افراد لفت‌داده» در اختیار ربات نمی‌گذارد.

## 🧰 پیش‌نیازها

- Python **3.10 یا بالاتر** پیشنهاد می‌شود.
- یک ربات تلگرام و توکن آن از [@BotFather](https://t.me/BotFather).
- شناسهٔ عددی حساب مدیر اصلی (`ADMIN_ID`).
- یک دیتابیس [Upstash Redis](https://upstash.com/) با REST URL و REST Token.
- کلید API یک سرویس هوش مصنوعی، برای هر مدلی که به کلید نیاز دارد.
- هاستی که اجرای پیوستهٔ پایتون و درخواست‌های خروجی HTTPS را پشتیبانی کند.

## 🚀 نصب و راه‌اندازی

### ۱. دریافت فایل‌ها

ZIP را استخراج کنید؛ ساختار اصلی پروژه چنین است:

```text
Neo-AI-Bot-Updated/
├── main.py
├── Bot_Ai_Beta_5_Model_Banner.py
├── requirements.txt
├── .env.example
├── Dockerfile
├── README.md
├── README_EN.md
├── docs/
└── assets/
    ├── banner.gif
    ├── features.gif
    └── divider.gif
```

`main.py` و `Bot_Ai_Beta_5_Model_Banner.py` هر دو یک نسخه از سورس هستند؛ برای اجرا فقط یکی را انتخاب کنید. روش پیش‌فرض این راهنما `main.py` است.

### ۲. ساخت دیتابیس Upstash

1. در [Upstash](https://upstash.com/) یک حساب ایجاد کنید.
2. یک دیتابیس Redis بسازید.
3. از صفحهٔ دیتابیس، مقادیر **REST URL** و **REST Token** را بردارید.
4. آن‌ها را در متغیرهای محیطی هاست وارد کنید؛ آدرس صفحهٔ داشبورد، جای REST URL نیست.

### ۳. تنظیم متغیرهای محیطی

در قسمت **Environment Variables / Secrets** هاست این چهار متغیر را تنظیم کنید:

| متغیر | مقدار |
|:---|:---|
| `BOT_TOKEN` | توکن دریافت‌شده از BotFather |
| `ADMIN_ID` | شناسهٔ عددی مدیر اصلی، بدون `@` |
| `UPSTASH_URL` | نشانی REST دیتابیس Upstash |
| `UPSTASH_TOKEN` | توکن REST دیتابیس Upstash |

فایل `.env.example` فقط نمونهٔ راهنماست؛ سورس فعلی مستقیماً از متغیرهای محیطی سیستم می‌خواند و فایل `.env` را به‌صورت خودکار بارگذاری نمی‌کند. مقادیر واقعی را در مخزن عمومی قرار ندهید.

### ۴. نصب وابستگی‌ها و اجرا

Linux / VPS / هاست پایتون:

```bash
python -m pip install -r requirements.txt
python main.py
```

اگر از نام اصلی اسکریپت استفاده می‌کنید:

```bash
python Bot_Ai_Beta_5_Model_Banner.py
```

### ۵. اجرا با Docker

بعد از قرار دادن متغیرهای محیطی در محیط اجرا:

```bash
docker build -t neo-ai-bot .
docker run --name neo-ai-bot --restart unless-stopped \
  -e BOT_TOKEN="$BOT_TOKEN" \
  -e ADMIN_ID="$ADMIN_ID" \
  -e UPSTASH_URL="$UPSTASH_URL" \
  -e UPSTASH_TOKEN="$UPSTASH_TOKEN" \
  neo-ai-bot
```

> اگر هاست شما بخش Start Command دارد، `python main.py` را انتخاب کنید. توکن‌ها و کلیدها را داخل Dockerfile یا کد hard-code نکنید.

## ⚙️ تنظیم اولیه از تلگرام

### مدیر اصلی

1. متغیرهای محیطی را تنظیم و برنامه را اجرا کنید.
2. در گفت‌وگوی خصوصی با ربات `/start` بفرستید.
3. دکمهٔ **پنل مدیریت ادمین** را باز کنید.
4. مدل‌ها را از پنل وارد کنید؛ تنظیمات در Redis ذخیره می‌شوند.

### افزودن مدل چت یا برنامه‌نویسی

اطلاعات را دقیقاً مطابق مستندات API ارائه‌دهنده وارد کنید:

1. **نام نمایشی**: برچسبی برای نمایش به کاربر.
2. **Base URL**: endpoint API، نه آدرس معمولی صفحهٔ وب.
3. **API Key**: کلید خصوصی سرویس؛ اگر API کلید نمی‌خواهد، از مقدار خالیِ موردپذیرش پنل استفاده کنید.
4. **Model Name**: شناسهٔ واقعی مدل.
5. **Vision**: مشخص کنید مدل ورودی تصویر را پشتیبانی می‌کند یا خیر، اگر این گزینه در فرم مدل نمایش داده می‌شود.

مدل‌های برنامه‌نویسی از مدل‌های چت مستقل‌اند. اگر هنوز مدل برنامه‌نویسی جداگانه‌ای تعریف نشده باشد، کد از مدل چت به‌عنوان fallback استفاده می‌کند.

### افزودن مدل تصویر

در پنل ادمین، **افزودن مدل عکس** را انتخاب کرده و نام، endpoint API، کلید، شناسهٔ مدل و در صورت وجود آدرس سایت را وارد کنید. آدرس سایت فقط لینک مرورگر است و جای endpoint API را نمی‌گیرد.

### افزودن مدل ویدیو

در پنل ادمین، **افزودن مدل ویدیو** را انتخاب کنید و فیلدهای زیر را مطابق API سرویس پر کنید:

- **Base URL / Endpoint:** آدرس واقعی API ساخت ویدیو.
- **API Key:** کلید سرویس، اگر لازم است.
- **Model Name:** شناسهٔ دقیق مدل.
- **Website URL:** لینک سایت برای حالت سایت‌محور.
- **Status URL Template:** قالب آدرس پیگیری وضعیت job، اگر سرویس job ID می‌دهد؛ فقط مطابق مستندات سرویس از `{id}` استفاده کنید.

اگر فقط سایت دارید، می‌توانید endpoint و اطلاعات API را خالی بگذارید و فقط Website URL را تنظیم کنید؛ در این حالت، کاربر به سایت هدایت می‌شود و ساخت مستقیم داخل تلگرام فعال نیست.

## 🎬 راهنمای کامل ساخت ویدیو در تلگرام

قابلیت ساخت ویدیو از یک مسیر مستقل برای مدل‌های ویدیو استفاده می‌کند؛ فهرست `VIDEO_MODELS` از مدل‌های چت، کدنویسی و تصویر جداست. ساخت مستقیم و ارسال ویدیو از داخل ربات در **گفت‌وگوی خصوصی** انجام می‌شود.

### ساخت ویدیو به‌عنوان کاربر

1. در گفت‌وگوی خصوصی ربات، `/start` را بفرست و از منوی اصلی **🎬 ساخت ویدیو** را انتخاب کن.
2. اگر چند مدل ویدیو در دسترس است، از بخش انتخاب مدل‌ها، مدل موردنظر را انتخاب کن. دسترسی به مدل‌های VIP تابع مجوز همان کاربر است.
3. بعد از فعال‌شدن حالت ویدیو، توضیح صحنه و نتیجه‌ای را که می‌خواهی بسازی در پیام بعدی بنویس.
4. روش جایگزین، ارسال دستور زیر در گفت‌وگوی خصوصی است:

   ```text
   /video A cinematic shot of a futuristic city at sunset
   ```

5. ربات درخواست را به API مدل انتخاب‌شده می‌فرستد، وضعیت پردازش را نمایش می‌دهد و در صورت دریافت خروجی قابل‌دریافت، فایل ویدیو را در تلگرام ارسال می‌کند.

در زمان پردازش، دکمهٔ **لغو درخواست** نمایش داده می‌شود. وضعیت‌هایی مانند قرارگرفتن در صف، آماده‌سازی، ساخت، رندر و نهایی‌سازی نمایش داده می‌شوند؛ درصد پیشرفت فقط وقتی نمایش داده می‌شود که سرویس‌دهنده مقدار واقعی آن را در پاسخ API برگرداند. در مرحلهٔ دانلود فایل نیز درصد دانلود، در صورت وجود اندازهٔ فایل، قابل نمایش است.

### پیکربندی مدل ویدیو توسط مدیر

از پنل مدیریت ادمین، گزینهٔ **افزودن مدل ویدیو** را انتخاب و مراحل زیر را تکمیل کن:

| فیلد | توضیح |
|:---|:---|
| نام نمایشی | نامی که در فهرست انتخاب مدل به کاربر نشان داده می‌شود. |
| Base URL | آدرس API واقعی سرویس؛ آدرس صفحهٔ اصلی سایت جایگزین API نیست. |
| API Key | کلید سرویس؛ برای Agnes لازم است. اگر سرویس کلید نمی‌خواهد، طبق راهنمای پنل `.` بفرست. |
| Model Name | شناسهٔ دقیق مدل در سرویس‌دهنده. |
| نوع API | تشخیص خودکار یا انتخاب آداپتور سازگار با سرویس. |
| پارامترهای ورودی | یک JSON object برای پارامترهای موردنیاز مدل، مثل مدت، نسبت تصویر یا وضوح؛ مطابق مستندات همان API. |
| Website URL | لینک اختیاری سایت سرویس؛ برای حالتی که کاربر باید در وب‌سایت سرویس کار کند. |

آداپتورهای آمادهٔ موجود در این نسخه عبارت‌اند از **Agnes، Runway، Replicate، fal.ai، Kling، Luma، درگاه‌های غیررسمی سازگار با OpenAI Videos، JSON عمومی و REST سفارشی**. تشخیص خودکار برای دامنه‌های شناخته‌شده انجام می‌شود؛ برای سرویس‌های دیگر نوع API را مطابق مستندات انتخاب کن یا از REST سفارشی استفاده کن. وجود آداپتور به معنی تضمین دسترسی یا اعتبار حساب در سرویس‌دهنده نیست.

### مدت، نسبت تصویر و تنظیمات ورودی

- مدت پیش‌فرض ویدیو از کارت ویرایش مدل قابل تنظیم است. مدیر می‌تواند یک عدد را به‌عنوان مدت پیش‌فرض تنظیم کند یا چند مدت پشتیبانی‌شده را با کاما ثبت کند؛ `auto` تشخیص خودکار را برمی‌گرداند. در جریان فعلی، درخواست با مقدار مدت تنظیم‌شده برای مدل (`seconds`) ساخته می‌شود و منوی جداگانه‌ای برای انتخاب مدت توسط کاربر وجود ندارد.
- محدودیت‌های شناخته‌شده در آداپتورهای فعلی: **Agnes Video 2.5: از ۴ تا ۱۲ ثانیه؛ Kling: از ۳ تا ۱۵ ثانیه؛ Luma: ۵ یا ۱۰ ثانیه**. برای مدل‌های دیگر، فقط مدت‌هایی را وارد کن که مستندات ارائه‌دهنده تأیید می‌کند.
- نسبت تصویر و وضوح، و گزینه‌هایی مانند صدا یا چندنما، در صورت پشتیبانی آداپتور از مقادیر مدل و `inputDefaults` خوانده می‌شوند؛ این فیلدها بین ارائه‌دهندگان یکسان نیستند.
- برای تنظیم یا ویرایش پارامترهای اضافی، گزینهٔ **پارامترهای ورودی مدل (JSON)** را باز کن. مقدار باید یک JSON object معتبر باشد؛ برای پاک‌کردن مقادیر ذخیره‌شده، `.` بفرست.

### REST سفارشی برای APIهای دیگر

اگر سرویس در فهرست آداپتورها نیست، نوع **REST سفارشی** را انتخاب کن و قالب درخواست را طبق مستندات سرویس تنظیم کن. نمونهٔ ساده:

```json
{
  "createPath": "/v1/videos/generations",
  "auth": "bearer",
  "payload": {
    "model": "{model}",
    "prompt": "{prompt}"
  },
  "statusUrlTemplate": "{base_url}/v1/jobs/{id}"
}
```

متغیرهای قابل استفاده در قالب شامل `{prompt}`، `{model}`، `{api_key}`، `{base_url}`، `{id}` و `{job_id}` هستند. تنظیمات پیشرفته می‌توانند `headers`، `bodyType` (`json` یا `form`)، `responseUrlTemplate`، `contentUrlTemplate` و `pollInterval` را هم مشخص کنند. حالت احراز هویت `auth` می‌تواند `bearer`، `key`، `raw` یا `none` باشد. فیلدهای سفارشی `jobIdField`، `statusField` و `videoUrlField` نیز باید با ساختار واقعی پاسخ API منطبق باشند. APIهایی که به OAuth، امضای HMAC یا multipart پیچیده نیاز دارند ممکن است به آداپتور اختصاصی احتیاج داشته باشند.

اگر API از همان ابتدا لینک مستقیم ویدیو را برگرداند، معمولاً نیازی به `statusUrlTemplate` نیست. اگر سرویس job غیرهم‌زمان ایجاد می‌کند، باید شناسهٔ job یا آدرس وضعیت/پیگیری و مسیر دریافت نتیجه را مطابق پاسخ API تنظیم کنی. قالب اشتباهِ polling باعث می‌شود ربات نتواند وضعیت یا فایل نهایی را پیدا کند.

### صف، لغو، دانلود و محدودیت‌ها

- پردازش ویدیو صف و worker مستقل دارد؛ تعداد workerها، سقف صف و هم‌زمانی درخواست به سرویس‌دهنده قابل تنظیم‌اند. مقدارهای پیش‌فرض سورس به‌ترتیب `VIDEO_JOB_WORKERS=1`، `VIDEO_JOB_QUEUE_LIMIT=1000` و `VIDEO_PROVIDER_CONCURRENCY=1` هستند.
- مهلت انتظار API با `API_TIMEOUT_SECONDS` کنترل می‌شود؛ مقدار پیش‌فرض سورس ۳۶۰۰ ثانیه است. مدت واقعی ساخت به سرویس‌دهنده و صف آن وابسته است.
- برای پاسخ‌های صریح محدودیت نرخ یا پرشدن صف، تلاش مجدد با رعایت سیاست سرویس و `Retry-After` انجام می‌شود. خطاهای مبهم شبکه در درخواست ایجاد job کورکورانه تکرار نمی‌شوند تا job یا هزینهٔ تکراری ایجاد نشود.
- سقف ارسال فایل ویدیویی در این نسخه **۴۹ مگابایت** است. اگر فایل بزرگ‌تر باشد یا آپلود تلگرام شکست بخورد، در صورت وجود لینک خروجی معتبر، ربات لینک مستقیم ویدیو را نمایش می‌دهد.
- اگر فقط `Website URL` تنظیم شده و `Base URL` خالی باشد، ربات لینک سایت سرویس را نشان می‌دهد؛ در این حالت ساخت ویدیو داخل تلگرام انجام نمی‌شود.
- ربات در صورت نبود مدل ویدیو، نامعتبر بودن endpoint، خطای احراز هویت، برنگشتن شناسهٔ job یا لینک خروجی، پیام خطای قابل‌بررسی نمایش می‌دهد. ابتدا Base URL، Model Name، API Key، نوع API و قالب پاسخ سرویس را کنترل کن.

### تاریخچهٔ گفتگو

چت جدید به‌صورت خودکار ثبت می‌شود. فهرست تاریخچه حداکثر ۷ گفتگو را نگه می‌دارد؛ عنوان از پیام آغازین گرفته می‌شود و زمان برای کاربر فارسی به وقت ایران نمایش داده می‌شود. علامت سبز نشان‌دهندهٔ گفت‌وگوی فعال است. حذف یک گفتگو از فهرست، طبق رفتار نسخه، رکورد گفت‌وگوی انتخاب‌شده را پاک می‌کند.

## 🧭 فرمان‌های گروه

### صدا زدن ربات

در گروه، درخواست خود را با یکی از شکل‌های زیر شروع کنید:

- `ربات درباره لینوکس توضیح بده`
- `روبات: این کد پایتون را بررسی کن`
- `بات یک مثال از API بنویس`
- `نئو سلام`
- `neo explain DNS`
- `tenet explain this error`
- `نئو-سلام` یا `نعو - سلام`
- `neo-hello` یا `تننت سلام`
- `@username سلام` (با منشن مستقیم ربات)

برای پاسخ به پیام خاص، می‌توانید به پیام ریپلای کنید و ربات را صدا بزنید. پاسخ‌دهی تابع تنظیمات گروه، privacy mode تلگرام و دسترسی ربات به پیام‌هاست.

### مدیریت گروه با Reply

برای فرمان‌های مربوط به کاربر، ابتدا به **پیام همان کاربر Reply** کنید:

| عبارت | کاربرد |
|:---|:---|
| `سکوت` یا `بی صدا` | محدودکردن پیام‌دادن کاربر تا رفع محدودیت |
| `سکوت 10` | سکوت به مدت ۱۰ دقیقه |
| `رفع سکوت` یا `آزاد` | برداشتن سکوت |
| `اخراج`، `بن` یا `/ban` | مسدودکردن کاربر از گروه |
| `حذف` یا `پاک` | حذف پیام هدف، در صورت داشتن مجوز |

### کنترل ربات و قفل گروه

| فرمان | کاربرد |
|:---|:---|
| `/bot سکوت` یا `/mute_bot` | متوقف‌کردن پاسخ‌های ربات در گروه |
| `/bot صحبت` یا `/unmute_bot` | فعال‌کردن دوباره پاسخ‌های ربات |
| `/lock` یا `/close` | قفل‌کردن ارسال پیام در گروه، اگر دسترسی کافی وجود داشته باشد |
| `/unlock` یا `/open` | بازکردن گروه |
| `/models` | مشاهده/انتخاب مدل‌های مجاز در گروه، طبق کنترل دسترسی نسخه |

فرمان‌های مدیریتی به ادمین‌بودن فرستنده و مجوزهای کافی ربات نیاز دارند. ادمین ناشناس گروه ممکن است با `ADMIN_ID` تطبیق داده نشود.

- افزودن، ویرایش، انتخاب و حذف مدل‌های چت، برنامه‌نویسی، عکس و ویدیو.
- افزودن، ویرایش و حذف کانال‌های اسپانسر.
- راهنمای تنظیم مدل‌ها داخل خود ربات.

## 🆕 بهبودهای جدید منو و تجربهٔ گفتگو

### منوی شیشه‌ای و صفحه‌کلید پایین

- گزینه‌های اصلی منوی شیشه‌ای از طریق صفحه‌کلید ثابت پایین چت نیز در دسترس هستند؛ چیدمان گزینه‌ها با توجه به سطح دسترسی کاربر و مدیر نمایش داده می‌شود.
- دکمهٔ مستقل **منوی شیشه‌ای** برای بازکردن منوی شیشه‌ای در نظر گرفته شده است؛ صفحه‌کلید پایین و منوی شیشه‌ای دو مسیر دسترسی جداگانه‌اند.
- مسیر بازگشت به **منوی اصلی** از صفحه‌کلید پایین اصلاح شده است تا کاربر بتواند بدون گیرکردن در زیرمنوها به منوی اصلی برگردد.
- اجرای دوبارهٔ `/start`، از جمله پس از پاک‌کردن گفت‌وگوی تلگرام و شروع مجدد، برای نمایش دوبارهٔ منو و صفحه‌کلید استفاده می‌شود.

### نمایش پاسخ هوش مصنوعی و لغو درخواست

- هنگام پردازش درخواست هوش مصنوعی، دکمهٔ **لغو درخواست** برای متوقف‌کردن درخواست در حال اجرا نمایش داده می‌شود.
- پس از آماده‌شدن پاسخ نهایی، پیام هوش مصنوعی بدون صفحه‌کلید کنترلی کاربر یا مدیر در زیر آن ارسال می‌شود.
- دسترسی به منوی شیشه‌ای و گزینه‌های صفحه‌کلید پایین مستقل از پیام پاسخ هوش مصنوعی باقی می‌ماند؛ بنابراین ابزارهای منو با کنترل‌های مربوط به یک پاسخ ترکیب نمی‌شوند.

### System Prompt قابل تنظیم برای مدل‌ها

مدیر می‌تواند از بخش اطلاعات/ویرایش مدل چت، دستورالعمل رفتاری مدل را تنظیم کند:

- **`CHAT`**: دستورالعمل ثابت و مشترک برای حالت گفت‌وگو.
- **`CODE`**: دستورالعمل ثابت برای حالت برنامه‌نویسی و پاسخ‌های کدنویسی.
- متن System Prompt در **Upstash Redis** ذخیره می‌شود تا پس از راه‌اندازی مجدد ربات نیز باقی بماند.
- حداکثر طول متن System Prompt برابر **۸۰۰۰ کاراکتر** است.
- برای پاک‌کردن متن فعلی، در ورودی مربوطه یک نقطه (`.`) ارسال کنید.
- System Prompt بر لحن، سبک و نحوهٔ پاسخ‌گویی مدل اثر می‌گذارد؛ به‌تنهایی ابزار جدید، دسترسی اینترنت یا قابلیت فنی تازه‌ای به مدل اضافه نمی‌کند.

### تشخیص واکنش‌های فارسی

تشخیص واکنش به پیام‌ها با توجه بیشتر به مفهوم و لحن جملهٔ فارسی انجام می‌شود؛ برای نمونه، جملهٔ حاوی عصبانیت نباید صرفاً به دلیل وجود یک واژهٔ مثبت، واکنش تأییدی بگیرد و لحن تمسخرآمیز یا خنده‌دار باید از جملهٔ جدی و مثبت تفکیک شود.

نمونه‌های مهم برای تفکیک لحن:

- `از دستش خیلی عصبانی‌ام`: جمله‌ای با احساس عصبانیت و بار منفی است و نباید به‌اشتباه واکنش تأییدی مانند `👍` بگیرد.
- `چه دلقک‌بازی‌ای 😂`: لحن شوخی/تمسخر و خنده دارد و باید از تأیید جدی تفکیک شود.
- `این حرکت خیلی عقده‌ای بود`: جمله‌ای انتقادی و منفی است و نباید به‌اشتباه واکنش تأییدی مانند `👍` بگیرد.

### مدیریت دسترسی مدل‌های رایگان و VIP

- هر مدل چت، کدنویسی، تصویر یا ویدیو می‌تواند از کارت مدیریت همان مدل به حالت **رایگان** یا **VIP** تغییر وضعیت دهد.
- مدیر می‌تواند راه ارتباطی پشتیبانی را تنظیم کند و برای هر کاربر، دسترسی یک مدل VIP را جداگانه اعطا یا لغو کند.
- فهرست مدل‌ها وضعیت رایگان/VIP را نشان می‌دهد. کاربری که مدل VIP را انتخاب کند، راه ارتباط با پشتیبانی و شرایط دریافت دسترسی را می‌بیند.
- درخواست دسترسی کاربر برای مدیر ارسال می‌شود و مدیر می‌تواند آن را تأیید یا رد کند.

### مدل کدنویسی و گزارش وضعیت

- مدل‌های برنامه‌نویسی از مدل‌های چت مستقل‌اند. اگر فهرست `CODE_MODELS` خالی باشد، نسخه‌ای که fallback آن فعال است از مدل چت برای درخواست‌های کدنویسی استفاده می‌کند.
- اگر `CODE_MODELS` خالی باشد ولی حداقل یک مدل چت در `AI_MODELS` وجود داشته باشد، حالت کدنویسی از مدل چت به‌عنوان جایگزین استفاده می‌کند و تست سلامت این وضعیت را به‌عنوان fallback فعال گزارش می‌دهد؛ این مورد به‌خودی‌خود خطای اتصال نیست. اگر هیچ مدل چتی هم تعریف نشده باشد، برای پاسخ‌گویی باید ابتدا مدل چت اضافه شود.
- در بررسی سلامت، وضعیت اتصال Telegram API و Upstash Redis (از جمله پاسخ `PING/PONG` دیتابیس، در صورت پشتیبانی مسیر بررسی) را از وضعیت پیکربندی مدل‌ها جداگانه بررسی کنید.

### صدا زدن ربات در گروه

برای صدا زدن ربات می‌توان از شکل‌های `ربات`، `روبات`، `بات`، `نئو`، `neo`، `neo-`، `نعو`، `تننت` و `tenet` استفاده کرد. منشن مستقیم `@username` ربات نیز پشتیبانی می‌شود. پاسخ‌دهی همچنان به تنظیمات گروه، Privacy Mode تلگرام و دسترسی ربات به پیام‌ها وابسته است.

### گزارش تست سلامت ربات

بخش **تست سلامت و بار ربات** در پنل ادمین چند بررسی غیرمخرب انجام می‌دهد، از جمله:

- دسترسی به Telegram Bot API و پاسخ `getMe`، همراه با بررسی اتصال Upstash Redis از طریق `PING/PONG`.
- معتبر بودن ساختار JSON و فهرست مدل‌های چت، کدنویسی، تصویر و ویدیو؛ وضعیت fallback مدل کدنویسی نیز جداگانه گزارش می‌شود.
- ثبت handlerهای پیام و callback، ساخت منوها، مسیر دکمه‌های منوی شیشه‌ای و صفحه‌کلید پایین، و گردش میان زیرمنوها.
- تشخیص فراخوانی گروه و منشن در ۱۵ نمونه، و بررسی وضعیت Privacy Mode تلگرام.
- ایمن‌بودن پیش‌نمایش پاسخ استریم‌شده و پنهان‌ماندن بخش‌های داخلی `<think>`.
- بررسی نمونه‌های تشخیص لحن و واکنش هوشمند فارسی در ۲۳ حالت، از جمله عصبانیت، شوخی/تمسخر، ناراحتی، کنایه، شادی و تشکر.
- بررسی برخی قواعد مدت ویدیو، لینک خروجی Agnes، سیاست retry برای پاسخ‌های 429/صف پر و وضعیت لحظه‌ای صف‌های پردازش.

این بررسی برای تست مسیرهای داخلی از مدل‌های پولی درخواست تولید نمی‌فرستد و قرار نیست دادهٔ واقعی کاربر را تغییر دهد؛ بااین‌حال، به‌تنهایی موفقیت تولید محتوا یا سلامت همهٔ APIهای خارجی را تضمین نمی‌کند. برای اطمینان از دسترسی یک ارائه‌دهنده، تنظیمات و اعتبار حساب همان سرویس را نیز بررسی کنید.

## 🔒 امنیت و حریم خصوصی

- `BOT_TOKEN`، توکن Redis و API Keyها را در GitHub عمومی منتشر نکنید.
- کلیدهای API را فقط در پنل مدیریتی امن یا Secrets هاست وارد کنید.
- مدیر اصلی با `ADMIN_ID` تعیین می‌شود؛ شناسهٔ عددی را استفاده کنید، نه نام کاربری یا آیدی گروه.
- قابلیت‌های تصویر و ویدیو بسته به شرایط سرویس‌دهنده، دادهٔ ارسالی و سیاست‌های آن سرویس عمل می‌کنند.
- تاریخچه و تنظیمات در دیتابیس Upstash نگهداری می‌شوند؛ قبل از استفادهٔ عمومی، سیاست نگهداری داده‌ها را با کاربران خود روشن کنید.
